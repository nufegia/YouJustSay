# 权限操作期间桌面输入卡顿：修复与验证

2026-10-30 用户报告修改权限或钥匙串授权后可能整机输入卡住。此前检查发现安装版与开发版并行运行；空闲采样未复现卡死。本次尚未取得卡死现场堆栈，因此下述为明确风险路径修复，不是已经证实的唯一根因。

- 全局修改型 event tap 只处理按键状态与消费决策，应用动作排队到回调返回后执行；授权或停止监听会使已排队动作失效。
- 收到系统 timeout/user-input 禁用通知后保持停用，不在回调里反复重新启用。此时普通输入放行，语音快捷键需要重启应用恢复。
- 可能弹窗的钥匙串读写前暂停监听，成功或失败后均解除暂停；嵌套暂停期间不会提前恢复。
- 麦克风授权、辅助功能修复及打开系统隐私设置时暂停监听；从设置返回应用后恢复。未重新激活应用之前快捷键保持暂停。
- 新启动副本若发现同 bundle ID 的实例，激活已有实例并退出，避免一般的重复启动场景；极短时间的并发启动竞争未做跨进程锁。

验证采用假凭据和合成键盘事件，覆盖暂停、恢复、超时后不重启、回调延迟及排队动作取消，不自动修改系统权限或触发用户钥匙串授权。需要用户在修复版中确认真实授权流程；发生卡顿时保留时间点及触发步骤以便进一步采样。

## 清除授权后重新申请

仅打开辅助功能设置不会重新建立被清除的应用权限记录。授权按钮必须在未授权时调用 `AXIsProcessTrustedWithOptions`（prompt 为 true）；成功清除旧授权后也走同一申请流程。由系统提示中的按钮打开设置，应用不同时另开设置窗口。已授权时的“管理”仍直接进入设置。授权交互期间继续暂停快捷键事件监听，返回应用后再刷新权限。
